### Operational Notes & Implementation Discoveries
- **OAuth2 Basic Auth Header Style (`AuthStyleInHeader`)**: `golang.org/x/oauth2/clientcredentials` defaults to sending client credentials in the POST request body (`client_secret_post`). Ory Hydra requires HTTP Basic Authentication in the `Authorization` header (`client_secret_basic`). Explicitly configured `AuthStyle: oauth2.AuthStyleInHeader` in `internal/kafka/sasl/tokensource.go`.
- **Hydra Client Audience Whitelist**: When requesting an audience claim (e.g., `KAFKA_OAUTH_AUDIENCE=kafka`), Ory Hydra rejects the token request unless the registered OAuth client explicitly includes that audience in its `audience` whitelist. Updated `internal/testhelpers/oauth.go` to accept custom audiences.
- **Kafka Topic Pre-Creation**: `NewKafkaWriter` sets `AllowAutoTopicCreation: false`. When publishing to real Kafka containers in integration tests, the permissions topic (`permissions.hook-service`) must be explicitly created beforehand to avoid broker `UNKNOWN_TOPIC_OR_PARTITION` errors.
- **Async Writer Batch Dispatch**: `kafkago.Writer` with `Async: true` buffers messages and dispatches them on background goroutines. When verifying message delivery in mock broker tests, a bounded poll loop is required to await in-flight batch transmission rather than asserting immediately after `WriteMessages` returns.
- **Standalone Mode Security Check Bypass**: In standalone mode (`KAFKA_BROKERS` is empty), Kafka security validation is bypassed so that the service does not fail to boot if placeholder auth/TLS variables are present without brokers. An informational log warning is emitted instead. In platform mode (`KAFKA_BROKERS` populated), full validation occurs via `ValidateKafkaSecurity`. The bypass is now expressed as a mode check inside `config.Validate` rather than as a branch in the startup wiring.
- **Startup Logic Relocated Out of `cmd` (Deviation from Tasks 4.1/4.2 as Originally Written)**: The original wiring put publisher selection, configuration validation, operator advisories, and `kafkago.Transport` assembly in two `cmd/serve.go` functions, `newPublisherSetup` and `buildKafkaTransport`, totalling 167 of the file's 495 lines. That made `cmd` the only subsystem wiring to reach across three packages and the only one importing `segmentio/kafka-go` directly, where every other subsystem (`db`, `openfga`, `tenants`, `authentication`) exposes a single `Config` plus constructor seam. It also forced `cmd` to grow its own generated mocks (`mock_logger.go`, `mock_monitor.go`, `mock_tracing.go`, roughly 730 lines) purely to test those two functions. Validation, mode derivation, and advisories moved to `internal/config`; transport and publisher assembly moved to `internal/kafka` behind `Config`/`NewPublisher`, mirroring `db.Config`/`db.NewDBClient`. `cmd/serve.go` fell from 495 to 377 lines, its Kafka footprint from 167 to 57 lines of mapping and reporting, and the three mock files and `cmd/serve_test.go` were deleted. No requirement changed; coverage moved with the code (`internal/config` 90.0% to 94.8%, `internal/kafka` 30.9% to 35.4%, `cmd` 22.4% to 20.3%, a denominator effect within the five percent guard).
- **Blank Broker Entries Now Yield Standalone Mode**: `DeploymentMode` derives from `KafkaBrokerList`, which trims entries and drops blanks, so `KAFKA_BROKERS=" "` resolves to standalone. Previously `len(specs.KafkaBrokers)` counted the whitespace entry and selected platform mode, while `ValidateKafkaBrokers` skipped the same entry as blank, producing a writer addressed at no usable broker. Deriving the mode and the publisher's broker list from one normalized list also removes the possibility of the reported mode diverging from the publisher in use, which the former single-function-returns-both arrangement existed to prevent. Left unspecified as a requirement by decision: the `platform-deployment-mode` scenarios "no broker addresses configured" and "one or more broker addresses configured" already read correctly under this behaviour, and that capability is out of scope for this change.
- **Standalone Advisories Aggregated, Platform Advisories Itemized**: `config.Warnings` reports ignored Kafka security settings in standalone mode as one aggregate notice, and reports the per-setting TLS contradictions (`KAFKA_TLS_CA_FILE` with TLS disabled, `KAFKA_TLS_INSECURE_SKIP_VERIFY` with TLS disabled, OAUTHBEARER without TLS) only in platform mode where those settings are actually consumed. This preserves the behaviour of the previous wiring, where the itemized diagnostics were reachable only because `buildKafkaTransport` ran solely when brokers were configured. Returning advisories as `[]string` rather than logging them in place is what allows them to be table-tested without a mock logger.
- **Transport Ownership Moved into the Publisher**: `PermissionPublisher.Close` now releases the transport's idle connections. Previously the startup wiring held the transport in a closure and composed a `close` function, which required nil checks in three places across two packages for the single "no custom transport" sentinel. The exported `NewPermissionPublisher` keeps its signature and leaves transport ownership with the caller, so `producer_test.go` and the integration tests were untouched.
- **Context-Aware Token Caching with `singleflight.Group` (Deviation from Decision 2)**: `design.md` originally proposed `oauth2.ReuseTokenSource`. In practice, `oauth2.TokenSource.Token()` does not accept `context.Context`, which would violate `AGENTS.md` Rule 1 by forcing a static `context.Background()` captured at startup, and would prevent linking OpenTelemetry child spans (`kafka.oauth.fetch_token`) to the dialer's trace context. Furthermore, `oauth2.ReuseTokenSource` serializes concurrent callers across network I/O with a `sync.Mutex`. We implemented `internal/kafka/sasl/tokensource.go` with `golang.org/x/sync/singleflight.Group` and `sync.RWMutex`, guaranteeing true single-flight deduplication across concurrent broker dials while ensuring caller deadlines or cancellations do not abort the shared fetch or trigger serial retries for other waiters.
